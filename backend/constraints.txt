# Origem: os dois jobs de backend do run 35411294770 (pos-merge do PR #54, HEAD

# POR QUE UM ARQUIVO DE CONSTRAINTS, E NAO `==` EM requirements.txt:
# a deriva observada estava nas TRANSITIVAS. `requirements.txt` declarava
# bcrypt>=4.2.1 e o CI instalava 5.0.0 — uma major inteira depois; starlette
# chegou a 1.6.0 sem que nada no repositorio pedisse isso. Fixar so as diretas
# nao alcanca starlette, pydantic-core ou anyio. Aqui `requirements.txt` continua
# significando INTENCAO (o que o projeto pede) e este arquivo significa RESOLUCAO
# (o que foi comprovado verde).
#
# POR QUE NAO HA MARKERS DE PLATAFORMA:
# um arquivo de constraints so limita QUAL VERSAO sera instalada; ele nunca
# obriga a instalar nada. `uvloop` e `httptools` continuam entrando apenas onde
# `uvicorn[standard]` os seleciona, e seguem ausentes no Windows exatamente como
# hoje. Transcrever markers incompletos aqui seria pior que nao ter nenhum.
#
# Como usar:
#   pip install -r requirements-dev.txt -c constraints.txt
#   pip install -r requirements.txt     -c constraints.txt
#

# congela tambem as depreciacoes hoje visiveis na suite, de proposito.
